# 教材结构化理解与复习系统 — 产品规格说明书

- 版本：v0.2
- 状态：实施基线
- Python 基线：3.13.15
- 首个验收对象：一本软考高级教材中的单章，约 20+ 页图片

## 1. 产品定位与目标

把教材从按页阅读的静态材料，转化为可追溯、可浏览、可理解、可检验、可复习的结构化知识空间。系统接收按顺序上传的教材页面图片，完成图像预处理、OCR/版面分析、原文 Markdown、层级识别、知识关系组织、图表处理、题目生成和间隔复习。

### 1.1 核心能力
1. 生成带稳定原文锚点的章节 Markdown。
2. 识别全书、章、节、小节、知识点、原文块等结构。
3. 建立全书架构、章节架构、知识点架构三层视图。
4. 图表可可靠重建时生成 Mermaid；否则保留原图。
5. 支持从全书到章节、知识点、原文的逐层下钻，以及原文反向追溯。
6. 基于审核通过的原文生成填空、选择、简答题。
7. 错题进入间隔复习队列，连续 5 次正确后标记掌握，之后低频抽查。
8. 大模型只生成候选内容；代码校验和人工审核决定内容能否进入正式知识空间。

### 1.2 不可妥协原则
- 正式知识节点、关系边和题目必须绑定有效原文来源。
- 原文、忠实摘要、AI 辅助讲解、AI 推断必须分层。
- 任意图谱节点都能定位原文；原文块能反查引用它的知识点、关系和题目。
- 置信度只是质量线索，不等于事实正确。
- OCR、模型或 Mermaid 失败不得导致原始图片和已完成中间结果丢失。
- 首期先完成单章闭环，但数据模型从第一天支持整本书。

## 2. 范围

### 2.1 本期范围
- 支持创建多本教材；MVP 先使用一本教材。
- 先导入单章，约 20+ 页。
- 多图上传、排序、删除、替换、页码校正。
- 图像预处理、OCR/版面分析、Markdown 和来源块锚点。
- 章/节/小节目录结构与知识点结构化。
- 全书、章节、知识点三层架构的数据模型和可视化基础。
- 章节提要、知识点关系、宏观关系图。
- 图片分类、Mermaid 候选重建、原图回退。
- 知识点下钻、原文高亮、反向引用。
- 填空、选择、简答题；简答题用户自评，不自动评分。
- 错题记录、复习调度、掌握状态。
- 审核队列、Markdown 和题库 JSON 导出。

### 2.2 暂不包含
- 多教材之间的完整知识图谱和跨书推理。
- 简答题自动评分。
- 多人协作和复杂权限体系。
- 强制所有图片 Mermaid 化。
- 无原文依据的扩展知识进入正式知识树。
- 自动生成未经审核的跨章因果结论。
- 复杂自适应学习算法；首期采用透明、可解释的间隔规则。

## 3. 三层知识架构（核心产品能力）

目录层级和知识关系是两种不同结构，不能只用一棵树表达。系统必须分别建模教材目录、知识点层级和知识关系网络。

### 3.1 全书架构 Book Map
回答：这本书整体讲什么？由哪些知识板块构成？章节之间如何衔接？

展示：
- 教材名称、版本、总章数、导入进度。
- 全书目录树：篇/部分（可选）→ 章 → 节。
- 主题板块：从已审核章节归纳主题；具体主题由教材内容决定，不预设固定分类。
- 章节主题矩阵：章节 × 主题，显示每章主要覆盖的主题。
- 章节关系：前置、递进、并列、对比、应用/支撑等。
- 学习路线：目录顺序、前置依赖或用户自定义顺序。
- 覆盖率和质量状态：未导入、已导入、待 OCR、待审核、已结构化。

约束：
- 只有已导入且达到审核门槛的章节参与正式知识图谱。
- 章节关系必须有证据，或明确标记为“AI 建议，待确认”。
- 未导入章节可以显示目录占位符，但不能虚构知识点和关系。

### 3.2 章节架构 Chapter Map
回答：本章知识怎样组织？作者先讲什么、再讲什么？核心主线是什么？

展示：
- 本章一句话定位、学习目标（区分原文目标与 AI 归纳）。
- 章 → 节 → 小节目录树。
- 按原文顺序组织的知识主线。
- 核心知识点、次级知识点、易混点。
- 本章知识关系图：包含、组成、步骤、因果、前置、对比、应用。
- 内容分布：每节知识点数量、原文页码范围、题目覆盖情况。
- 本章在全书中的位置：显示前置/后续章节及其关系依据。

### 3.3 知识点架构 Knowledge Map
回答：一个知识点由什么构成？与什么相似或不同？学习它需要什么？它会应用在哪里？

首期关系类型：
- contains：包含/组成。
- prerequisite：学习前置。
- sequence：步骤或时序先后。
- causes：因果。
- contrast：对比/易混淆。
- association：一般关联。
- application：应用到/用于。
- implements：实现/落实。
- example_of：实例属于。
- same_as：同义或等价，谨慎使用。

关系方向必须明确。一般关联不得伪装成因果或前置关系。每条边保存证据、来源类型、置信度和审核状态。

### 3.4 三层视图的视觉表达
- 目录/包含关系：树形或缩进结构。
- 前置/流程关系：有向图。
- 对比关系：双栏对照或成对节点。
- 因果关系：有向边并显示证据。
- 一般关联：虚线或弱化边。
- 原文依据：节点详情中显示页码、块 ID 和原图定位。

交互要求：
- 缩放、平移、适配画布。
- 节点搜索、高亮、展开和折叠。
- 按关系类型过滤。
- 点击节点打开详情。
- 从节点跳转原文。
- 显示/隐藏低置信度或待审核关系。
- 图谱过大时按章节/主题折叠，避免一次铺满。
- 提供列表/树形替代视图，保证可访问性和小屏可用。

### 3.5 知识内容分层
每个知识节点内容分为：
1. 原文依据：原文引用或原文块关联，不随意改写。
2. 忠实摘要：对教材内容的忠实概括，必须有来源。
3. 辅助讲解：便于理解的 AI 解释，明确标记为辅助内容。
4. 推断备注：跨段综合或补充联系，默认待审核，不进入正式知识关系。
5. 考试关注点：必须标注依据；无原文依据时标记为经验建议。

## 4. 用户流程

### 4.1 导入流程
1. 创建教材，填写书名、版本、考试方向等元信息。
2. 创建章节并按页序上传图片。
3. 校正页序、教材页码、旋转和质量问题。
4. 系统生成 OCR/版面结果与 Markdown 草稿。
5. 切分原文块并建立锚点。
6. 识别标题层级、图表和候选知识点。
7. 代码校验并形成审核任务。
8. 用户审核关键问题，批准后进入正式知识空间。

### 4.2 学习流程
1. 从全书架构了解知识板块和章节关系。
2. 进入章节架构，查看本章主线、目录和知识联系。
3. 选择知识点，查看知识点架构及相关知识。
4. 打开核心知识卡片。
5. 跳转原文块，并可查看原始页面图片。
6. 进入自测，答题后查看答案和原文依据。
7. 错题进入复习队列；简答题用户自评“会/不会”。

## 5. 功能需求

### 5.1 教材与图片管理
- 支持多本教材，MVP 先验证一本。
- 图片记录原始文件名、文件哈希、上传时间、页序、教材页码。
- 支持拖拽排序、删除、替换、旋转、重新识别。
- 保留原始图片，不覆盖原文件。
- 预处理包括方向校正、去噪、透视校正、裁边、分辨率和模糊度检查。
- 低质量图片允许继续处理，但标记质量问题。
- 文件哈希用于识别重复上传，提示用户，不静默丢弃。

### 5.2 OCR、版面分析与 Markdown
识别正文、标题、页眉页脚、页码、表格、公式、图片、图注、脚注、代码块。

特别要求：
- 页眉页脚、扫描水印、重复期刊/平台标识等噪声单独分类，不能混入正文。
- 脚注默认作为独立 footnote 块；正文保留引用标记，不得无条件拼入段落。
- 支持目录页、跨页段落和跨页表格的后续合并。
- Markdown 保留标题层级、列表、表格、公式、图注和图片引用。
- 表格优先结构化；复杂表格可保留原图并附结构化转录。
- 代码块和公式保留识别文本，并标记低置信度风险。

锚点建议格式：
<!-- src: book=book_id, chapter=ch_03, page=12, block=p12_b3, bbox=120,340,880,520, confidence=0.93 -->

锚点规则：
- source_block.id 在同一文档版本内稳定，建议由 chapter、page、block 顺序和内容指纹组合生成。
- 重新 OCR 不直接覆盖旧版本；创建新处理版本，并维护旧 ID 到新 ID 的映射。
- bbox 使用原始图像坐标，并保存原图宽高。
- 正文段落、标题、表格、图注、公式、脚注均有独立块 ID。
- OCR 低置信度文本标记并进入审核队列。

### 5.3 目录与层级结构
结构：Book → Chapter → Section → Subsection → KnowledgeNode；SourceBlock 是可被多个知识点引用的来源资产。

- 标题层级由编号规则、版面特征和模型候选共同识别。
- 代码检查编号连续性、层级跳跃、空标题、重复标题和跨页标题。
- 目录树是教材组织结构；知识点树是学习组织结构，二者分开。
- 知识点与原文块采用多对多关系：一个知识点可引用多个块，一个块也可支撑多个知识点。
- 知识点至少绑定一个有效来源块才能申请正式审核。
- 无来源或来源失效的节点进入 needs_review，不进入正式知识视图。

### 5.4 图片分类与 Mermaid
图片分类：流程图、架构图、状态图、时序图、ER 图、表格、公式图、界面截图、照片、其他。

- 流程/架构/状态/时序/简单关系图优先尝试 Mermaid。
- 复杂表格、公式密集图、照片、复杂界面图保留原图。
- 保存原图、图注、页码、bbox、分类、重建状态、Mermaid 源码和 fallback 原因。
- Mermaid 必须语法校验并实际渲染；失败自动回退原图。
- 图像重建不得阻塞 Markdown 和知识树生成。
- 保留 OCR/模型提取的图元素清单，供人工核对，不能只比较节点/边数量。

### 5.5 全书架构生成
- 根据目录元数据建立全书目录树。
- 根据已审核章节知识节点生成主题候选；主题必须追溯到章节/知识点。
- 章节主题矩阵显示覆盖程度，并展示证据。
- 章节关系边区分目录顺序、教材明确引用、前置建议、主题关联等来源类型。
- 教材明确关系与 AI 推测关系必须区分。
- 未导入章节只显示目录信息，不生成知识点。
- 全书图谱支持从章节节点进入章节架构。

### 5.6 章节架构与提要
生成一句话提要、学习目标、核心知识点列表、按教材顺序的知识主线、节/小节树、本章关系图、易混点和对比表。每项都附 source_refs；无依据推断默认待审核。

### 5.7 知识点卡片与关系图
知识点字段包括名称、定义、忠实摘要、辅助讲解、核心要点、组成、步骤、条件、适用范围、易混点、前置知识、关联知识、应用、原文来源、页码、原图定位、质量状态和审核记录。

交互：
- 点击知识点显示邻接关系和关系说明。
- 支持结构树/关系图/对比视图切换。
- 支持关系过滤、搜索、展开/折叠。
- 每条关系边显示证据摘要和原文入口。
- 原文块反向显示引用它的知识点、题目和关系。

### 5.8 自测题生成
题型：
- 填空：挖术语、数字、步骤、分类关键词；避免虚词、歧义和上下文不足。
- 选择：正确项有原文依据；干扰项优先来自同章易混知识点，且不得与正确项同义。
- 简答：给出标准答案、要点清单和来源；用户自评会/不会，不做自动评分。

题目保存 question_id、knowledge_id、题型、题干、选项、答案、解释、难度、source_refs、审核状态、模型/提示版本和创建时间。

审核：
- 答案必须在原文中出现或可由原文直接推出。
- 填空答案不能是停用词、虚词或歧义短语。
- 选择题必须只有一个正确答案；干扰项不能与正确项同义。
- 检查重复题、答案一致性、来源存在性。
- 未审核题目不进入正式题库和复习队列。

### 5.9 间隔复习
复习状态按知识点和题目两种粒度保留；不能因某一道题答对就直接判定整个知识点掌握。

首期规则：
- 答错：连续正确数归零、错误计数加一，缩短下次复习间隔。
- 答对：连续正确数加一，按 1、2、4、7、15、30 天推进。
- 连续 5 次正确：标记 mastered，转入低频抽查，例如 30 天后。
- 掌握后答错：撤销掌握并重新进入短间隔队列。
- 简答题用户自评“会”视为正确，“不会”视为错误。
- 保留完整答题历史、题目版本、用户答案/自评、时间和复习间隔。
- 时间统一存 UTC，界面按本地时区显示。
- 产品称为间隔复习方案，不宣称严格复现某个心理学定律。

### 5.10 审核工作台
审核队列包括 OCR 低置信度块、页眉页脚/脚注/水印分类异常、标题层级冲突、无来源知识点、无证据关系、Mermaid 失败或图元素不匹配、题目答案不确定/选项歧义/重复题。

审核动作：批准、修改后批准、驳回、暂缓；保留审核人、时间、修改前后内容和原因。

## 6. 数据模型

建议 PostgreSQL；单机 MVP 可先 SQLite。通过 SQLAlchemy 2.x 和 Alembic 控制迁移。

核心表：
- books：教材元信息、版本、导入状态。
- chapters：所属教材、章序、标题、页码范围、处理状态。
- sections：章内目录节点，支持 parent_id 和 sort_order。
- chapter_pages：原始图片、页序、教材页码、尺寸、哈希。
- processing_runs：OCR/模型处理版本、配置、状态和错误。
- source_blocks：原文块、bbox、页码、类型、置信度、处理版本。
- figures：图片/图表、Mermaid 候选和回退状态。
- knowledge_nodes：知识点树节点、摘要、解释、状态。
- knowledge_sources：知识点与来源块多对多关联。
- relations：章节/知识点之间的关系边。
- questions：题目、答案、解释、来源、审核状态。
- review_states：用户对知识点/题目的掌握状态。
- answer_logs：每次作答和自评。
- audit_issues：待审核问题。
- audit_events：审核操作历史。
- book_themes / chapter_themes：主题及证据关联，可在后续任务包引入。

关键约束：
- 正式知识节点至少有一个有效 knowledge_sources 记录。
- 正式关系必须有两个有效端点和 evidence_refs。
- 正式题目必须有来源块和审核记录。
- SourceBlock 关联 processing_run_id。
- 删除页面时，引用不静默级联删除；标记失效并产生审核问题。
- 目录层级、知识点层级、知识关系边分别存储。

## 7. 技术架构

采用模块化单体，不在 MVP 过早引入微服务。

- 后端：Python 3.13.15 + FastAPI。
- 前端：React + TypeScript（最终由技术验证任务包确认；也可评估 Vue）。
- 数据库：SQLite 起步，SQLAlchemy 2.x + Alembic；需要并发时迁移 PostgreSQL。
- 文件：本地文件系统；数据库只存相对路径、哈希和元数据。
- 异步处理：MVP 可用数据库任务表 + 后台 worker；复杂后再评估 RQ/Celery。
- OCR：定义 Provider 接口，允许本地 OCR 或多模态 API，不绑定单一厂商。
- 模型输出：Pydantic Schema + 业务规则审核 + 人工审核。
- 可视化：Mermaid 用于流程/关系图；目录树和复杂关系网络使用专门图组件，并保留列表视图。
- 配置：环境变量/本地配置；API Key 仅后端读取，.env 不入库。
- 测试：pytest，覆盖 API、服务、数据模型、导入流水线和核心规则。

### 7.1 Python 环境基线

- Python 3.13.15。
- 仓库提供 .python-version，内容为 3.13.15。
- Windows PowerShell 初始化命令：
  - py -3.13 -m venv .venv
  - .\.venv\Scripts\Activate.ps1
  - python --version
  - python -m pip install -U pip
  - pip install -e ".[dev]"
- 验收必须确认 python --version 为 3.13.15。
- 依赖必须实测 Python 3.13.15 兼容性。若某 OCR/图像库不兼容，隔离 Provider 或替换实现，不擅自降低 Python 基线。

## 8. 服务/API 边界

按业务能力划分模块，不要求首版全部暴露为公共 API：
- Books：教材创建和查询。
- Chapters：章节、目录和页序。
- Uploads：图片上传、排序、替换、删除。
- Processing：处理任务、状态、重试。
- SourceBlocks：原文块、页面定位、反向引用。
- Knowledge：知识树、知识点详情、来源。
- Maps：全书/章节/知识点架构和关系过滤。
- Questions：题库、答题、简答自评。
- Reviews：今日待复习、计划、掌握状态。
- Audits：待审核列表和审核操作。
- Exports：Markdown、JSON 导出。

## 9. 非功能需求

- 20+ 页单章异步处理，前端可查看阶段进度。
- 单页失败可重试，不影响其他页面和原始图片。
- 中间产物持久化，任务重启后可续跑。
- 锚点在同一处理版本内稳定；新版本通过映射维护历史引用。
- 关键操作有日志，错误可定位到页面、块、任务和 Provider。
- API Key 不进入前端、不写入 Git。
- 支持本地数据备份和恢复。
- 首期优先正确性、可追溯性和可恢复性，不追求高并发。
- 大图谱按需加载/折叠，避免全量渲染卡顿。

## 10. 里程碑与验收

### M0：项目骨架和技术验证
Python 3.13.15 环境、项目结构、配置、测试、健康检查。干净环境可安装、启动、运行测试。

### M1：单章图片导入与原文资产
上传、排序、原图保存、页码管理、基础预处理、OCR Provider、SourceBlock、Markdown。20+ 页不丢失；每页状态可见；Markdown 块可定位原图。

### M2：章节目录与知识树
目录识别、标题层级、知识点候选、来源绑定。知识点可人工修正；无来源节点不能批准。

### M3：三层架构可视化
先落地章节架构和知识点架构；全书架构先支持目录和已导入章节，再逐步增加主题与跨章关系。全书→章节→知识点→原文链路可用，关系边能查看证据。

### M4：图表处理与审核工作台
图片分类、Mermaid 重建、渲染回退、OCR/知识/关系审核。重建失败不丢原图、不阻塞正文；审核操作留痕。

### M5：题库与复习
填空/选择/简答生成、审核、作答、错题队列、复习调度。答题记录可追溯；连续 5 次正确和掌握后答错的状态转换正确。

### M6：整合、导出与真实教材验收
Markdown/题库 JSON 导出、备份恢复、端到端测试。使用真实 20+ 页章节完成导入—审核—学习—答题—复习全流程。

## 11. 首章验收指标

1. 20+ 页图片完整保存，页序可修改，失败可重试。
2. Markdown 可读；表格、公式、脚注、图注有明确处理结果。
3. 候选知识点来源绑定率目标 ≥80%；最终批准知识点来源覆盖率必须为 100%。
4. 目录结构可人工修正，无静默层级跳跃。
5. 章节主线和知识关系图可展示，正式关系边 100% 有证据。
6. 任一批准知识点可下钻到原文块和原始页面。
7. Mermaid 失败时原图仍可查看。
8. 题目可追溯来源，审核通过率和驳回原因可统计。
9. 连续 5 次正确后掌握状态正确；掌握后答错会重新进入复习。
10. 全书视图只呈现已导入/已审核证据，不虚构未导入章节内容。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| OCR 错误污染知识结构 | 保留原图、置信度、块级审核和版本化处理 |
| 页眉/水印/脚注混入正文 | 版面区域分类、重复文本检测、脚注独立建模 |
| 大模型幻觉 | 来源强制绑定、Schema 校验、规则审核、人工批准 |
| 知识关系过度推断 | 关系类型白名单、证据字段、推测状态默认隐藏 |
| 全书图谱过于复杂 | 主题聚合、按需展开、目录/图谱双视图 |
| Mermaid 误重建 | 语法、渲染、人工语义核对；失败保留原图 |
| 题目质量不佳 | 题目审核、重复检测、答案证据检查 |
| Python 3.13 依赖不兼容 | 早期技术验证、Provider 隔离、锁定已验证依赖 |
| 过早做成复杂平台 | 模块化单体、单章闭环优先、任务包分批验收 |
